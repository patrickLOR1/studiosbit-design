# Estudios audiovisuales — Diseño y edición de videos

**Ámbito:** idea → gancho → guion / storyboard → producción → edición → subtítulos → revisión → adaptación por red.

## Cuando el video demuestra un producto digital (v0.9)
- Usar [fundamentos UX con fuentes](../../references/FUNDAMENTOS_DISENO_LITERATURA.md) para ordenar información y mostrar estados reales de la interfaz. Aplicar las heurísticas como criterios editoriales, no como estudios propios.
- Si se explica la construcción de una web, mostrar arquitectura proporcional conforme a [guía web](../../references/ARQUITECTURA_WEB_GUIA.md), sin atribuir seguridad, escalabilidad ni conversión a un mockup.

## Método por pieza
1. **Objetivo y audiencia:** atención cualificada, confianza, autoridad, demostración o consulta. Evitar métricas vanidosas como único criterio.
2. **Gancho visual y verbal** en los primeros segundos; una pregunta o tensión real, sin clickbait engañoso.
3. **Secuencia:** problema/tesis → ejemplo propio o autorizado → decisión o transformación visible → aprendizaje → CTA.
4. **Storyboard y shot list:** indicar segundo aproximado, toma, movimiento, sobreimpresión, audio, voz, transición y responsable del recurso.
5. **Edición:** ritmo ligado al sentido, contraste, jerarquía, B-roll, screen recording legítimo, microanimación y sound design licenciado. No saturar con efectos.
6. **Adaptaciones:** vertical 9:16 para Reels/TikTok, títulos dentro de safe areas, legibilidad sin sonido, subtítulos revisados, portada coherente y alternativa carrusel/Facebook.
7. **Revisión:** retención visual, locución, errores ortográficos, marca, derechos, consentimiento de personas, edición de pantalla con datos privados ocultos, CTA y archivo final.

## Nuevo lote audiovisual SB-36 a SB-41
- **SB-36:** recorrido de landing por capítulos; mostrar primero la propuesta de valor y después el recurso visual, usando solo diseños propios.
- **SB-37:** microinteracción de tab bar antes/después en grabación de prototipo propio; explicar feedback y accesibilidad.
- **SB-38:** demostración de CMS con datos ficticios: editar reseña → vista previa → publicar → verificar.
- **SB-39:** comparación de tres direcciones visuales para un mismo brief conceptual, argumentando jerarquía y color.
- **SB-40:** microexplicación de A/B: hipótesis → variante → medición consentida → decisión; resultados solo si son reales.
- **SB-41:** demostración QA: recorrer un formulario hasta persistencia en una base de pruebas, mostrar error recuperable y validación.
- **Regla de producción:** si se graba código, test o dashboard, ocultar claves y datos personales, usar fixtures sintéticos y no afirmar integraciones/impactos no verificados.

## Series originales de Studios.Bit
- **Bit Audit:** problema observado → corrección conceptual real → por qué mejora UX (sin ridiculizar).
- **1 Bit de Diseño:** principio → contraste antes/después propio → aplicación.
- **Dentro del Estudio:** brief → opciones → decisión → resultado verificable.
- **Mitos de negocios digitales:** explicación con contexto y límites.
- **Construimos en Codex:** concepto → prototipo → QA, sin prometer resultados inexistentes.

## Entregable de Codex
Concepto de video, plataforma, objetivo, gancho A/B, guion de voz, tabla de tomas por tiempos, texto en pantalla, storyboard, instrucciones de edición, subtítulos, CTA, copy, thumbnail y checklist. Si el usuario solo grabará, entregar lista de tomas suficiente para que edición sea autosuficiente.
